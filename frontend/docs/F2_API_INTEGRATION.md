# F2 — API integration foundation

## Backend contract audit

The frontend follows the checked-in [`shared/api-contracts/openapi.json`](../../shared/api-contracts/openapi.json), OpenAPI 3.1, MCP-RI Backend API 1.0.0, generated by the FastAPI app. The API design summary is [`docs/API_DESIGN_SPECIFICATION.md`](../../docs/API_DESIGN_SPECIFICATION.md); route implementation is in `src/mcp_ri/api/routers.py`. The local base URL used by backend docs is `http://127.0.0.1:8000/api/v1` and FastAPI docs are available at `/api/v1/docs` while the server runs.

The API has no authentication. Use only the documented loopback development service unless an authenticated access layer is added. CORS defaults to `http://localhost:3000` and `http://127.0.0.1:3000`, allows GET/POST/OPTIONS, allows `Content-Type` and `X-Request-ID`, and exposes `X-Request-ID`. If the Next origin differs, set backend `MCP_RI_CORS_ORIGINS`; CORS is not access control.

## Frontend architecture

- `lib/api/config.ts`: validates public base URL, mock flag, environment and timeout.
- `lib/api/client.ts`: typed GET/POST client, JSON envelope parsing, request IDs, timeout/cancel behavior, and normalized safe errors. Only GET and POST are exposed because those are the methods in current OpenAPI.
- `lib/api/types.ts`: manually maintained transport types derived from the OpenAPI 3.1 components. Open-ended record payloads remain JSON values so saved Phase 9–13 fields are not discarded.
- `lib/api/endpoints.ts`: path builders and query serialization for only exposed routes.
- `lib/services/`: health, learner, behavioral state, evidence, cognitive estimate, representation, and trajectory calls.
- `hooks/use-api-health.tsx`: one health request when the shell mounts, plus explicit user retry. No background polling. Health state is shared by the shell and dashboard.
- `components/shared/`: connection, data source, loading, error, empty, response timestamp, and retry presentation.

Service functions return the API's `data`, request ID, and HTTP status. An empty success body is explicitly returned as `data: undefined`; services do not turn it into empty objects or fabricated records. Generic types are compile-time types from OpenAPI; nested artifact data is not runtime schema-validated in the browser.

## Endpoint mapping

| Service | OpenAPI operation(s) | Frontend module |
|---|---|---|
| Health | `GET /health` | `health.service.ts` |
| Learner index/detail | `GET /learners`, `GET /learners/{learner_id}` | `learner.service.ts` |
| Behavioral snapshot | `GET /learners/{learner_id}/state` | `learner-state.service.ts` |
| Cognitive estimate | `GET /learners/{learner_id}/cognitive-state` | `cognitive-state.service.ts` |
| Evidence and annotations | `GET /learners/{learner_id}/evidence`, `GET /learners/{learner_id}/evidence/{evidence_id}` | `evidence.service.ts` |
| Representation plans | `GET /learners/{learner_id}/representations`, `GET /learners/{learner_id}/representations/{plan_id}` | `representation.service.ts` |
| Trajectory, history, diversions | GET routes under `/learners/{learner_id}/trajectories` and `/diversions` | `trajectory.service.ts` |
| Trajectory writes | `POST /learners/{learner_id}/trajectories`, `POST /learners/{learner_id}/trajectories/{trajectory_id}/actions` | `trajectory.service.ts` |

The evidence routes include grouping/alignment annotations on evidence records; there are no standalone group, alignment, or conflict endpoints. No direct endpoints exist for content, interaction submission, representation execution, model evaluation, diversion writes, or resumption writes. No frontend methods are created for these missing operations. Trajectory action enum is exactly `activate | pause | advance_step`.

## Environment

Copy `frontend/.env.example` to `frontend/.env.local` and set:

```dotenv
NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8000/api/v1
NEXT_PUBLIC_USE_MOCK_DATA=false
NEXT_PUBLIC_API_TIMEOUT_MS=10000
```

- `NEXT_PUBLIC_API_BASE_URL` must be an absolute HTTP(S) URL. Non-local production URLs must use HTTPS. Do not include credentials or secrets.
- `NEXT_PUBLIC_USE_MOCK_DATA=true` explicitly selects the fictional dashboard walkthrough. Mock mode skips API health requests and carries a visible demo banner. Invalid values are a configuration error.
- `NEXT_PUBLIC_API_TIMEOUT_MS` accepts an integer from 250 to 120000; the default is 10000.
- Changes to `NEXT_PUBLIC_*` values require restarting Next.js.

Real API mode never falls back to mock data. Missing configuration shows disconnected status; invalid configuration or an HTTP/protocol error shows error; network/timeout shows disconnected; a successful health response shows connected, with degraded health identified separately. Only an actual successful response can show connected.

## Run locally

1. Complete backend setup and artifact indexing as described in [`docs/BACKEND_INTEGRATION_REPORT.md`](../../docs/BACKEND_INTEGRATION_REPORT.md).
2. Run the API from repository root, for example:

   ```bash
   PYTHONPATH=src .venv-api/bin/uvicorn mcp_ri.api.main:app --reload --host 127.0.0.1 --port 8000
   ```

3. Copy `frontend/.env.example` to `frontend/.env.local`.
4. In `frontend/`, run `npm install` if dependencies are not installed, then `npm run dev`.
5. Check the top-bar connection indicator or open `http://127.0.0.1:8000/api/v1/health` directly. Retry from the indicator after starting/restarting the API.

At F2 completion, the dashboard used the real health module summary and `GET /learners` index count in API mode. F3 now retains those health/module details on the learner overview and adds record-level views; see [`F3_LEARNER_EXPERIENCE.md`](F3_LEARNER_EXPERIENCE.md). It does not show an invented real-mode objective, learner identity, progress, or lesson. Fictional scenario content appears only when `NEXT_PUBLIC_USE_MOCK_DATA=true`.

## Errors and connection state

Network failures and timeouts become disconnected state. Non-2xx responses become `ApiError` with status and safe backend `code`, `message`, optional `fields`, and `request_id`; malformed successful JSON/envelopes become protocol errors. The UI shows safe messages and request IDs when available. Raw response bodies, stack traces, and low-level network errors are not rendered. The connection check runs once and can be retried; learner index loading has its own retry.

## Tests

No test framework was installed in the frontend. Focused integration foundation tests use the project TypeScript compiler and Node's built-in `node:test`/`assert` runner, with no added package:

```bash
cd frontend
npm run test:api
```

The script compiles API/services and a transport type-check file into ignored `.api-test-dist`, then runs isolated tests for envelope success, POST serialization, network errors, HTTP 4xx/5xx, timeout, invalid JSON, empty response, health mapping, connection failure classification, mock/real configuration, and no silent fallback. These are frontend unit tests; none require a running backend. Type checking is included in the compile step.

## Known limitations and dependencies

- The F3 learner experience supports pseudonymous record selection and read-only state/evidence/plan/trajectory screens. Authentication, activity delivery, interaction submission, full researcher detail pages, and trajectory/diversion mutations remain unavailable.
- API transport types need review/regeneration whenever the checked-in OpenAPI changes. No OpenAPI generator dependency was added.
- Generic Phase 9–13 JSON fields retain their values as `JsonValue`; detailed UI-specific schemas and runtime validation remain future work.
- The backend has no auth, content provider, interaction-submission route, model inference/evaluation routes, or diversion/resumption writes. These cannot be completed in the frontend.
- Backend health can be `degraded` while reachable. A failure to index configured artifacts may make learner routes return 503; the UI reports the error and does not replace it with synthetic data.
